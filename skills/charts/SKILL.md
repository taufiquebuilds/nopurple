# nopurple-charts

AI-made charts look the same everywhere: a rainbow of colours, an exploded pie with a drop shadow, gridlines, a legend in a box, labels rotated 45 degrees, and a title like "Lead Source Distribution Overview". They are busy and they don't say anything.

This skill makes charts that make one point clearly, the way the best newspaper graphics do. Most of the work is deciding what the chart is *for*. The styling follows from that.

## The rules

1. **The title is the finding.** "Google Ads brought 42% of all leads: 86 of 204" beats "Leads by Channel". Put the topic in a small label (kicker) above it.
2. **Check every number in the title against the data before you write it.** Do the arithmetic, and don't claim "more than all others combined" or "doubled" without computing it. A false headline on an honest chart is still a false chart.
3. **One accent colour, for the one thing the title talks about.** Everything else is neutral grey. Rainbow palettes make every bar shout, so none is heard.
4. **Label values directly** on or next to the marks. Remove the legend, gridlines and axis that the labels make redundant.
5. **Be honest with scales.** Bars start at zero. Don't use dual axes or 3D, and don't stretch the aspect ratio to exaggerate a trend.
6. **Pick the chart for the comparison** (see `references/chart-types.md`). A sorted horizontal bar chart beats a pie almost every time. Long category names never go on a rotated axis; use horizontal bars.
7. **Readable at the size it will be seen.** Text is 14 px or more at final size, and a chart for a slide or phone is simpler than one for a report.
8. **Look at it.** Render the chart and view the image before you hand it over.

## Workflow

### 1. Find the point

Look at the data and answer: what is the one comparison that matters? Biggest, change over time, before and after, share of a whole, or a ranking. Write the headline as a full sentence with the number. If the data doesn't support a clear point, say so to the user rather than forcing one.

If you need a number you don't have, ask, or leave a visible `[?]`. Never invent data. The source line says only what the user told you about where the data came from; for sample or made-up data, write "Sample data." Don't copy the source from an example.

### 2. Choose the chart

Use `references/chart-types.md`. The short version:

| The point is | Use |
| --- | --- |
| Ranking or comparing categories | Horizontal bars, sorted, highlight one |
| Change over a few periods | Vertical bars |
| A trend over many points | A line, with the latest value labelled |
| Two or three series over time | Lines with direct labels at the ends, highlight one |
| Before and after for several items | A slope chart, or a dot plot |
| Share of a whole | A single stacked bar, or say it in words; a pie only for 2 or 3 parts |
| One number | Don't chart it: use a big number with context |

### 3. Build it

**Python (matplotlib):** use `scripts/chart_style.py`. It applies the theme and draws the common charts with the rules built in:

```python
import sys; sys.path.insert(0, "<skill-dir>/scripts")
from chart_style import hbar, finish

fig, ax = hbar(["Google Ads", "Organic", "Referrals"], [86, 54, 31], highlight="Google Ads")
finish(fig, kicker="Leads by channel, October 2026",
       title="Google Ads brought 42% of all leads: 86 of 204",
       source="<where the user said the data is from, or Sample data.>",
       path="leads.png")
```

It provides `hbar`, `bar`, `line`, `slope` and `finish`, plus 6 themes (`paper`, `ink`, `swiss`, `forest`, `sand`, `mono`) that match nopurple-slides. Read the docstrings for options.

**Other tools** (Plotly, Chart.js, Recharts, Vega-Lite, Excel, Google Sheets): follow `references/libraries.md`. It has the settings to remove legends and gridlines, start at zero and colour one series.

### 4. Render and look

Open the image and check:
- Is the headline true, and is its number visible in the chart?
- Is the accent on exactly one thing?
- Are labels readable, unclipped and not overlapping?
- Do the bars start at zero?
- Would it still read if printed in black and white? (Highlight with brightness, not just hue.)

Fix and render again.

### 5. Check the code

```sh
python3 <skill-dir>/scripts/chart_check.py chart.py   # also .js, .ts, .jsx, .tsx, .json, .html
```

It flags pies, exploded slices, shadows, 3D, rainbow colour lists and colour maps, truncated bar axes, dual axes, rotated labels, gridlines, topic titles and emoji in titles. Fix what applies. A flag can be wrong, for example a pie with two slices; when you keep one, say why.

### 6. Hand over

Give the user the image path, the headline, the numbers behind it (so they can check them in a few seconds), and any `[?]` or sample-data labels.

## When the user brings an existing chart

Run `chart_check.py` on the code if there is code. If there's only an image, describe what to change using the rules above. Then rebuild it with the same data, and show both versions side by side if you can.
